Create the Redis-backed session management service for multi-turn conversation context.

Purpose: Sessions are the backbone of the conversational experience -- they allow the system to maintain context across multiple messages within a 30-minute window, track pending follow-up questions, and associate conversation turns with specific task topics. Without sessions, every message would be processed in isolation.

Output: Working SessionService with Redis storage, TTL management, and full unit tests.

  <action>
    1. Install dependencies:
       ```bash
       npm install ioredis @liaoliaots/nestjs-redis
       ```
       Note: ioredis v5 ships its own TypeScript definitions. Do NOT install @types/ioredis.

    2. Update `.env.example` -- add Redis URL:
       ```
       REDIS_URL=rediss://default:xxxxx@endpoint.upstash.io:6379
       ```
       Add it below the existing DATABASE_URL entry. Also add ANTHROPIC_API_KEY if not already present:
       ```
       ANTHROPIC_API_KEY=sk-ant-xxxxx
       ```

    3. Create `src/session/session.types.ts`:
       - Define `SessionStatus` type: `'idle' | 'awaiting_follow_up'`
       - Define `ConversationTurn` interface:
         ```typescript
         interface ConversationTurn {
           role: 'user' | 'assistant';
           content: string;
           timestamp: string; // ISO 8601
         }
         ```
       - Define `TopicContext` interface:
         ```typescript
         interface TopicContext {
           id: string;           // UUID for this topic
           parentTaskId: string | null;
           taskIds: string[];    // All task IDs created/modified in this topic
           conversationHistory: ConversationTurn[];
           pendingFollowUps: string[];  // Question texts awaiting answers
         }
         ```
       - Define `SessionState` interface:
         ```typescript
         interface SessionState {
           id: string;
           userId: string;
           status: SessionStatus;
           activeTopic: TopicContext | null;
           createdAt: string;  // ISO 8601
           updatedAt: string;  // ISO 8601
         }
         ```
       - Export `SESSION_TTL = 1800` constant (30 minutes in seconds -- per user locked decision)
       - Export all interfaces and types

    4. Create `src/session/session.service.ts`:
       - Injectable NestJS service
       - Constructor: inject Redis via `@InjectRedis() private readonly redis: Redis` from `@liaoliaots/nestjs-redis` and ioredis
       - Private `key(userId: string): string` -> returns `session:${userId}`
       - `async get(userId: string): Promise<SessionState | null>`:
         - `redis.get(this.key(userId))`
         - Return parsed JSON or null
       - `async set(userId: string, state: SessionState): Promise<void>`:
         - Update `state.updatedAt` to current ISO timestamp
         - `redis.set(this.key(userId), JSON.stringify(state), 'EX', SESSION_TTL)` -- single command (per pitfall 1 in research)
       - `async create(userId: string): Promise<SessionState>`:
         - Generate new session with `id: randomUUID()`, status 'idle', activeTopic null, timestamps
         - Call `this.set(userId, session)`
         - Return session
       - `async getOrCreate(userId: string): Promise<SessionState>`:
         - Get existing session or create new one
         - Return `{ session, isNew }` tuple so caller knows if session expired
       - `async refreshTtl(userId: string): Promise<void>`:
         - `redis.expire(this.key(userId), SESSION_TTL)`
       - `async clear(userId: string): Promise<void>`:
         - `redis.del(this.key(userId))`
       - `async updateTopic(userId: string, topic: TopicContext): Promise<void>`:
         - Get session, set activeTopic, set status based on pendingFollowUps (if non-empty -> 'awaiting_follow_up', else 'idle')
         - Save back with `this.set()`
       - `async addConversationTurn(userId: string, turn: ConversationTurn): Promise<void>`:
         - Get session, push turn to activeTopic.conversationHistory
         - Save back
       - Use NestJS Logger for any error logging (consistent with Phase 1 pattern)

    5. Create `src/session/session.module.ts`:
       - NestJS Module
       - Imports: `RedisModule.forRootAsync({ useFactory: () => ({ config: { url: process.env.REDIS_URL } }) })`
         - Use `@nestjs/config` ConfigService pattern instead of direct process.env:
           ```typescript
           RedisModule.forRootAsync({
             imports: [ConfigModule],
             inject: [ConfigService],
             useFactory: (config: ConfigService) => ({
               config: {
                 url: config.getOrThrow<string>('REDIS_URL'),
               },
             }),
           })
           ```
       - Providers: [SessionService]
       - Exports: [SessionService]
  </action>
