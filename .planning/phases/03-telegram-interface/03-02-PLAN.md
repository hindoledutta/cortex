Create `src/telegram/services/orchestrator.service.ts` -- the central coordination service for all Telegram message flows.

**Constructor dependencies (all injected via NestJS DI):**
- ClassificationService, DecompositionService, FollowUpService, EnrichmentService, CommentProcessingService (from LlmModule)
- SessionService (from SessionModule)
- TaskService (from TaskModule)
- WorkspaceService (from WorkspaceModule)
- CommentService (from CommentModule)
- VoiceService, MessageFormatterService (from TelegramModule)
- PrismaService (from PrismaModule) -- used for direct telegramMsgId updates on tasks after sending bot messages

**Methods to implement:**

1. `async handleText(ctx: Context): Promise<void>`:
   - Extract `chatId = String(ctx.chat.id)` and `text = (ctx.message as any).text`
   - **Reply-to detection first:** If `(ctx.message as any).reply_to_message?.from?.is_bot`, extract `reply_to_message.message_id` and call `this.commentService.findTaskByTelegramMsgId(BigInt(replyMsgId))`. If task found, delegate to `this.handleComment(ctx, task, text)` and return.
   - Get or create session: `const { session } = await this.session.getOrCreate(chatId)`
   - Refresh TTL: `await this.session.refreshTtl(chatId)`
   - Get pending follow-ups: `const pendingFollowUps = session.activeTopic?.pendingFollowUps ?? []`
   - Classify: `const classification = await this.classification.classify(text, pendingFollowUps)`
   - Route based on `classification.intent`:
     - `'new_brain_dump'`: call `this.handleBrainDump(ctx, chatId, text)`
     - `'follow_up_answer'`: call `this.handleFollowUpAnswer(ctx, chatId, text, session)`
     - `'command'`: reply with "Use /tasks, /workspace, /help, or /settings"
     - `'unclear'`: reply with a helpful message suggesting brain dump or /help

2. `async handleVoice(ctx: Context): Promise<void>`:
   - Send typing indicator: `await ctx.sendChatAction('typing')`
   - Get file link: `const voice = (ctx.message as any).voice; const fileLink = await ctx.telegram.getFileLink(voice.file_id)`
   - Transcribe: `const transcription = await this.voice.transcribe(fileLink)`
   - Show transcription: `await ctx.reply(this.formatter.formatTranscription(transcription), { parse_mode: 'HTML' })`
   - Process as brain dump (auto-proceed per project decision -- no approval step): call `this.handleBrainDump(ctx, String(ctx.chat.id), transcription)`

3. `async handleCallback(ctx: Context): Promise<void>`:
   - Extract match from `(ctx as any).match` (regex captures from @Action decorator)
   - Parse action and taskId: `const action = match[1]; const taskId = match[2]`
   - Get default workspace: `const workspace = await this.workspace.getDefault()`
   - If action is 'edit': reply with "Reply to this message with the changes you'd like to make for this task" and call `ctx.answerCbQuery('Edit mode')` and return
   - For done/start/defer: map action to TaskStatus (`done -> 'done'`, `start -> 'in_progress'`, `defer -> 'deferred'`)
   - Call `await this.taskService.update(taskId, workspace.id, { status: mappedStatus })`
   - Edit original message to show updated status: `await ctx.editMessageText(...)` with updated task info and keyboard
   - **Always** call `await ctx.answerCbQuery('Task updated!')` (prevents loading spinner)

4. `async handleCommand(ctx: Context, command: string): Promise<void>`:
   - Switch on command:
     - `'tasks'`: Get default workspace, call `taskService.findAll(workspace.id)`, format each task with `formatter.formatTaskBreakdown()` and send individually (max 10 tasks). If > 10, show count of remaining. If 0, show "No tasks" message. Store sent message IDs on tasks via `this.prismaService.task.update({ where: { id: task.id }, data: { telegramMsgId: BigInt(sentMsg.message_id) } })` (same direct Prisma pattern as handleBrainDump).
     - `'workspace'`: Show current default workspace. Parse args from `(ctx.message as any).text` -- if `/workspace work` or `/workspace personal`, call `workspaceService.setDefault(name)` and confirm. If no arg, show current default and usage hint.
     - `'help'`: Reply with a help message listing all commands (/tasks, /workspace, /help, /settings) and usage tips (send text for brain dump, send voice, reply to task for comment).
     - `'settings'`: Show current settings (default workspace, session TTL info). This is informational-only for v1.

5. `private async handleBrainDump(ctx: Context, chatId: string, text: string): Promise<void>`:
   - Send typing indicator: `await ctx.sendChatAction('typing')`
   - Get default workspace: `const workspace = await this.workspace.getDefault()`
   - Decompose: `const result = await this.decomposition.decompose(text, workspace.name)`
   - If `result.needs_decomposition` and `result.parent_task`:
     - Create parent task via `taskService.create({ title: result.parent_task.title, description: result.parent_task.description, priority: result.parent_task.priority, deadline: result.parent_task.deadline, workspaceId: workspace.id, sourceInput: text })`
     - Create sub-tasks in order via `taskService.create({ ..., parentId: parentTask.id, position: idx, workspaceId: workspace.id })`
     - Format and send: `const { text: msgText, extra } = this.formatter.formatTaskBreakdown(parentTask, createdSubTasks)`
     - Send message and store telegramMsgId: `const sentMsg = await ctx.reply(msgText, extra)` -- then store the mapping by calling `this.prismaService.task.update({ where: { id: parentTask.id }, data: { telegramMsgId: BigInt(sentMsg.message_id) } })` directly in OrchestratorService. This avoids modifying TaskService and is consistent with the Prisma-direct pattern used elsewhere for cross-cutting concerns. **Inject `PrismaService` into OrchestratorService constructor** alongside the other dependencies.
   - If not needs_decomposition: create single task, format, send
   - Handle follow-up: if `result.follow_up_needed && result.detected_gaps.length > 0`:
     - Generate follow-up questions: `const followUp = await this.followUp.generateFollowUp(...)` with summary of created tasks, task IDs, and detected_gaps
     - Update session topic with task IDs, pending follow-ups
     - Send first follow-up question: `await ctx.reply(this.formatter.formatFollowUpQuestion(followUp.questions[0].text), { parse_mode: 'HTML' })`
     - Store all question texts in session's pendingFollowUps
   - Add conversation turn to session

6. `private async handleFollowUpAnswer(ctx: Context, chatId: string, text: string, session: SessionState): Promise<void>`:
   - Send typing indicator
   - Get workspace and existing tasks from session's activeTopic.taskIds
   - Fetch existing tasks info: map taskIds to ExistingTaskInfo via `taskService.findOne()`
   - Call `enrichmentService.processFollowUpAnswer(text, existingTasks, workspace.id, session.activeTopic?.parentTaskId)`
   - Reply with enrichment summary
   - Clear pending follow-ups from session (set to empty array)
   - Update session status to idle
   - Add conversation turn

7. `private async handleComment(ctx: Context, task: any, commentText: string): Promise<void>`:
   - Create comment: `await this.commentService.create(task.id, commentText, 'user', BigInt((ctx.message as any).message_id))`
   - Extract action items: `const extraction = await this.commentProcessing.extractActionItems(commentText, task.title, task.description)`
   - If `extraction.has_action_items && extraction.action_items.length > 0`:
     - Format suggested sub-tasks and send to user with confirmation inline buttons: `confirm:subtask:{parentTaskId}` for accept, `reject:subtask:{parentTaskId}` for dismiss
     - For v1 simplicity: auto-create the sub-tasks via TaskService and show them (skip confirmation buttons to reduce complexity). The user can always delete unwanted sub-tasks.
   - Reply with confirmation: "Comment added to task: {task.title}" plus any action items found

**Important patterns:**
- Always call `ctx.sendChatAction('typing')` before LLM operations
- Catch errors at the method level, log them, and send a user-friendly error message via ctx.reply
- Use NestJS Logger for all logging
- Use `try/catch` around all external service calls (LLM, Whisper, Prisma) with graceful fallbacks
