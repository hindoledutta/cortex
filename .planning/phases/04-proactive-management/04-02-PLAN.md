1. Create `src/scheduler/reminder.service.ts`:
   - Injectable service with dependencies: `SchedulerService` (for `boss`), `NotificationService`, `SettingsService`, `PrismaService`
   - Implements `OnModuleInit` to register the deadline-reminder worker

   a. `onModuleInit()`:
      Register the pg-boss worker for 'deadline-reminder' jobs:
      ```typescript
      await this.scheduler.boss.work('deadline-reminder', async (job) => {
        await this.handleDeadlineReminder(job.data as { taskId: string });
      });
      ```

   b. `private async handleDeadlineReminder(data: { taskId: string })`:
      **CRITICAL: Re-validate task state before sending notification** (Pitfall 1 from research).
      - Fetch task from database: `prisma.task.findUnique({ where: { id: data.taskId } })`
      - Guard: if task is null, or `task.deletedAt` is not null, or `task.status` is `done`, log "skipping reminder for completed/deleted task" and return
      - Call `this.notifications.sendDeadlineReminder({ id: task.id, title: task.title, deadline: task.deadline! })`
      - Log the successful reminder send

   c. `async scheduleReminder(taskId: string, deadline: Date, perTaskLeadMinutes?: number | null)`:
      - Get global settings: `const settings = await this.settings.get()`
      - Determine lead time: `const leadMinutes = perTaskLeadMinutes ?? settings.reminderLeadMinutes`
      - Calculate fire time: `const fireAt = new Date(deadline.getTime() - leadMinutes * 60 * 1000)`
      - If fireAt is in the past, use `undefined` for startAfter (fires immediately)
      - Send pg-boss job:
        ```typescript
        await this.scheduler.boss.send('deadline-reminder', { taskId }, {
          startAfter: fireAt > new Date() ? fireAt.toISOString() : undefined,
          singletonKey: `deadline:${taskId}`,
          retryLimit: 2,
          expireInMinutes: 60,
        });
        ```
      - `singletonKey` ensures one reminder per task. Sending a new job with the same key replaces the old one (handles deadline changes -- Pitfall 2).

   d. `async cancelReminder(taskId: string)`:
      - Cancel by deleting jobs with the singleton key. Use:
        ```typescript
        const jobs = await this.scheduler.boss.getJobById(`deadline:${taskId}`);
        ```
        **NOTE**: pg-boss v12 may not support getJobById by singletonKey. Alternative approach: since `singletonKey` prevents duplicates, simply do nothing -- the handler already validates task state. If the task is completed/deleted, the handler skips silently. However, to clean up, use:
        ```typescript
        await this.scheduler.boss.cancel(`deadline:${taskId}`);
        ```
        If `cancel` doesn't accept singletonKey, just rely on the handler's re-validation guard. Log the cancellation attempt either way.

2. Create `src/scheduler/polling.service.ts`:
   - Injectable service with dependencies: `PrismaService`, `NotificationService`, `SettingsService`
   - Import `Cron` from `@nestjs/schedule`
   - Import `TaskStatus` from Prisma generated enums
   - Use Logger from `@nestjs/common`

   a. `@Cron('0 * * * *')` -- Run every hour on the hour (check if current hour matches user's notificationHourUtc)
      `async checkStaleTasks()`:
      - Get settings: `const settings = await this.settings.get()`
      - Check if current UTC hour matches `settings.notificationHourUtc`. If not, return early. This approach avoids timezone issues (Pitfall 4) by running hourly and only acting at the configured hour.
      - Calculate cutoff date: `const cutoff = new Date(); cutoff.setDate(cutoff.getDate() - settings.checkInAfterDays)`
      - Query stale tasks:
        ```typescript
        const staleTasks = await this.prisma.task.findMany({
          where: {
            status: TaskStatus.in_progress,
            updatedAt: { lt: cutoff },
            deletedAt: null,
            parentId: null,  // Only parent tasks -- avoid spam for individual sub-tasks
            NOT: {
              children: {
                some: {
                  updatedAt: { gte: cutoff },
                  deletedAt: null,
                },
              },
            },
          },
        });
        ```
        The `NOT` clause handles Pitfall 6 -- skip check-in if any child was recently updated.
      - For each stale task, wrap in try/catch (per-task error tolerance):
        ```typescript
        for (const task of staleTasks) {
          try {
            await this.notifications.sendCheckInPrompt(task);
          } catch (err) {
            this.logger.error(`Failed to send check-in for task ${task.id}`, err);
          }
        }
        ```

   b. `@Cron('0 * * * *')` -- Same hourly pattern with notificationHourUtc check
      `async resurfaceDeferredTasks()`:
      - Get settings, check hour match (same pattern as above)
      - Query deferred tasks ready to resurface:
        ```typescript
        const tasks = await this.prisma.task.findMany({
          where: {
            status: TaskStatus.deferred,
            deferredUntil: { lte: new Date() },
            deletedAt: null,
          },
        });
        ```
      - For each task (per-task error tolerance with try/catch):
        - **Send notification FIRST, then update status** (Pitfall 5 -- if notification fails, task stays deferred and retries tomorrow)
        - `await this.notifications.sendDeferredResurface(task)`
        - `await this.prisma.task.update({ where: { id: task.id }, data: { status: TaskStatus.active, deferredUntil: null } })`
      - Log count of resurfaced tasks
