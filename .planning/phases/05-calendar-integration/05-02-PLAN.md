**3. Create TimeBlockService** (`src/calendar/services/time-block.service.ts`):

Inject `CalendarService` and `ConfigService`.

Methods:

`async suggestTimeBlocks(params: { calendarId: string; deadline: Date; effortMinutes: number; timezone: string }): Promise<TimeBlockSuggestion[]>`

Implementation:
- Read working hours from config: `WORKING_HOURS_START` (default 9), `WORKING_HOURS_END` (default 17) -- use `this.config.get<number>('WORKING_HOURS_START', 9)` pattern
- Query freeBusy from CalendarService: `this.calendarService.queryFreeBusy({ calendarId, startDate: new Date(), endDate: deadline, timezone })`
- Generate candidate time slots during working hours between now and deadline:
  - Iterate day by day (skip weekends: Saturday=6, Sunday=0)
  - For each working day, create slots of `effortMinutes` duration within working hours
  - Check each candidate against busy slots -- if no overlap, it's available
  - Use the timezone string for display formatting but compute slots in UTC internally
- Return top 3 available slots as `TimeBlockSuggestion[]` with human-readable labels
- If no slots available (all booked or deadline too close), return empty array

Label format: Use `Intl.DateTimeFormat` with the user's timezone for formatting. Example: "Mon Mar 2, 9:00 AM - 11:00 AM"

Helper method: `private overlaps(slot: TimeSlot, busySlots: BusySlot[]): boolean` -- returns true if slot overlaps with any busy slot.

Add new methods:

**`async handleCalendarAction(ctx: Context, taskId: string): Promise<void>`**

This is the main calendar flow triggered by the "Calendar" button:

1. Fetch the task by ID (using workspace.getDefault() + taskService.findOne())
2. Show typing indicator: `ctx.sendChatAction('typing')`
3. Extract calendar info via LLM: `calendarExtraction.extract(task.title, task.description, childTitles)`
4. If `extraction.person_names.length > 0`, resolve names: `contactService.resolveNames(extraction.person_names, workspace.id)`
5. If `resolution.unresolved.length > 0`:
   - Store pending calendar state in session: save the taskId, resolved emails, unresolved names queue, and extraction result
   - Use `session.updateTopic()` to store a `pendingCalendarAction` in the session's activeTopic (extend the conversationHistory or use pendingFollowUps as a temporary channel)
   - Prompt for the first unresolved name: `ctx.reply(formatter.formatContactPrompt(unresolved[0]))` with parse_mode HTML
   - The contact prompt response will be handled by the text handler (see handleContactResponse below)
   - Answer callback query: `ctx.answerCbQuery('Resolving contacts...')`
   - Return early (event creation continues after all contacts resolved)
6. If all names resolved (or no names):
   - Determine calendar parameters:
     - `calendarId`: workspace.googleCalendarId ?? 'primary'
     - `timezone`: `this.config.get<string>('USER_TIMEZONE', 'America/New_York')`
     - `startTime`: If task.deadline exists, default to 1 hour before deadline. If no deadline, default to next working hour.
     - `endTime`: startTime + (extraction.estimated_hours ?? 1) hours
     - `attendeeEmails`: resolution.resolved.map(r => r.email)
   - Create event: `calendarService.createEvent({ calendarId, summary: task.title, description: task.description, startTime, endTime, timezone, attendeeEmails, taskId })`
   - Update task estimatedEffort if extraction provided one: `prisma.task.update({ where: { id: taskId }, data: { estimatedEffort: Math.round((extraction.estimated_hours ?? 1) * 60) } })`
   - Reply with success: `ctx.reply(formatter.formatCalendarEventCreated(task.title, formattedStartTime))` with parse_mode HTML
   - Answer callback query: `ctx.answerCbQuery('Event created!')`

**`async handleSuggestTimeBlocks(ctx: Context, taskId: string): Promise<void>`**

Triggered by "Suggest Time" button:

1. Fetch the task
2. If task has no deadline: reply "This task has no deadline set. Add a deadline first to get time-block suggestions." and return
3. Show typing indicator
4. Extract effort estimate: `calendarExtraction.extract(task.title, task.description, childTitles)`
5. Calculate effort in minutes: `Math.round((extraction.estimated_hours ?? 1) * 60)`
6. Get suggestions: `timeBlockService.suggestTimeBlocks({ calendarId: workspace.googleCalendarId ?? 'primary', deadline: task.deadline, effortMinutes, timezone })`
7. If no suggestions: reply "No available time blocks found before the deadline. Your calendar may be full."
8. Store suggestions in session state (so accept handler can reference them): use session.updateTopic or a Map in memory. For v1 simplicity, store in a class-level `Map<string, { taskId: string; suggestions: TimeBlockSuggestion[] }>` keyed by chatId.
9. Format and send: `ctx.reply(formatter.formatTimeBlockSuggestions(task.title, suggestions))` -- this includes accept/dismiss buttons
10. Answer callback query: `ctx.answerCbQuery('Finding time blocks...')`

**`async handleTimeBlockAccept(ctx: Context, suggestionIndex: number): Promise<void>`**

Triggered by "Accept" button on time-block suggestion:

1. Retrieve stored suggestions from the in-memory Map using chatId
2. Get the selected suggestion by index
3. Fetch the task from stored state
4. Create calendar event with the selected time block: `calendarService.createEvent({ calendarId, summary: task.title, startTime: suggestion.slot.start, endTime: suggestion.slot.end, timezone, taskId })`
5. Reply with success message
6. Clear stored suggestions
7. Answer callback query

**`async handleTimeBlockDismiss(ctx: Context): Promise<void>`**

Simple: clear stored suggestions, reply "Time block suggestions dismissed.", answer callback query.

async handleTimeBlockCallback(ctx: Context): Promise<void> {
