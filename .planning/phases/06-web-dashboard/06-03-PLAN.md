   - Import `useDroppable` from `@dnd-kit/react`

   - Props: `tasks: Task[]`, `onStatusChange: (taskId: string, workspaceId: string, newStatus: TaskStatus) => void`
   - Define `STATUS_COLUMNS` array: `['captured', 'active', 'in_progress', 'done', 'blocked', 'deferred']`
   - Group tasks by status into columns object
   - Only show parent tasks (filter `tasks.filter(t => !t.parentId)`) -- sub-tasks are shown as indicators on parent cards
   - Wrap columns in `DragDropProvider` with `onDragEnd` handler:
     - Extract `taskId` from `source.id` and `newStatus` from the target column
     - Find the task to get its `workspaceId`
     - Call `onStatusChange(taskId, workspaceId, newStatus)`
   - Render horizontal flex container with `KanbanColumn` for each status
   - Add horizontal scrolling (`overflow-x-auto`) for narrow screens

   - Export the columns array

   - Simple preset filter for deadlines (not a date picker -- keep it lightweight)
   - Props: `value: string | undefined`, `onChange: (value: string | undefined) => void`
   - Options as shadcn Select: "All deadlines", "Overdue", "Due this week", "Due this month", "No deadline"
   - Each option maps to a filter function applied client-side (not sent to API)

4. **Create `dashboard/src/components/filters/FilterBar.tsx`:**
   - Compose WorkspaceFilter, StatusFilter, and DeadlineFilter into a horizontal bar
   - Props: all the individual filter props (workspace, status, deadline values + onChange handlers)
   - Layout: horizontal flex with gap, wrapping on mobile
   - Include ViewToggle component (from Plan 02) at the right end of the bar

5. **Update `dashboard/src/routes/index.tsx` (the main dashboard page):**
   - Import: `useTasks`, `useUpdateTask`, `useWorkspaces`, `KanbanBoard`, `TaskTable`, `FilterBar`, `ViewToggle`
   - Use the search params from TanStack Router for view, workspace, status, and deadline filters
   - Fetch tasks using `useTasks(workspace)` -- pass workspace ID to API for server-side filtering
   - Fetch workspaces using `useWorkspaces()`
   - Apply client-side filters for status and deadline:
     - Status filter: if `status` array is non-empty, filter tasks where `task.status` is in the array
     - Deadline filter: use `date-fns` to compare task deadlines against filter presets (overdue = before today, this week = within 7 days, this month = within 30 days, no deadline = null)
   - Render FilterBar at top with current filter values and navigate handlers to update URL search params
   - Render ViewToggle next to filters
   - Conditionally render `KanbanBoard` or `TaskTable` based on `view` search param
   - Wire `KanbanBoard.onStatusChange` to `useUpdateTask` mutation:
     ```typescript
     const updateTask = useUpdateTask();
     const handleStatusChange = (taskId: string, workspaceId: string, newStatus: TaskStatus) => {
       updateTask.mutate({ id: taskId, workspaceId, data: { status: newStatus } });
     };
     ```
   - Show loading state (using shadcn Skeleton or simple "Loading..." text) while tasks are being fetched
   - Show error state if fetch fails

6. **Update search param validation in the route** to include `deadlineFilter`:

   ```typescript
     deadline: search.deadline as string | undefined,
   }),
   ```

7. **Ensure all filter changes update URL search params** using `navigate({ search: (prev) => ({ ...prev, filterName: newValue }) })`. This ensures:

   - Filters carry over when toggling between kanban and list
